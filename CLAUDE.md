# CLAUDE.md

Guidance for Claude Code working in this repository.

## What this is

A breastfeeding, diaper and medicine tracker used on an Android phone at all hours, often
one-handed and half-asleep. It is a single-page web app installed to the home screen as a PWA,
not a native app.

**Her phone holds the log.** The owner runs the same app on his phone to record what he does —
nappies, mostly — and sends it over as a message she pastes in (1.13). That is the whole of the
multi-user story: two independent logs, one of which is the real one, and a merge that only ever
adds. There is no shared state, no account, and no second copy of the truth.

It is live at **https://sporadic92.github.io/Nursing-log/**, served by GitHub Pages from the
branch below at `/ (root)`. Pushing to that branch *is* deploying. The repository is public
because Pages is paid on private repos; nothing private lives here, since the log itself never
leaves the phone.

Everything is stored in `localStorage` on her device. There is no server, no account, no
analytics, and no network dependency after first load.

## Branch

Work on `claude/breastfeeding-tracker-android-hg00uu`, and **push straight to it — no need to
ask, and no need for a pull request.** The owner has said so. Pages publishes from that branch,
so a push is a live change on a phone someone is relying on: run the suite first, and don't
push a change you haven't tested. If a session is handed a different branch to work on, finish
there and then merge it here, still without asking. Anywhere else needs a reason.

(The `-android-` in the name is vestigial: the project started as a Kotlin/Compose app and was
abandoned within the hour because the owner has no Android Studio and needed it working the
same day. Don't revive that approach.)

## Non-negotiables

These come from how the app is actually used. Check any change against them.

1. **No build step, no dependencies, no framework.** `index.html` is the whole app — markup,
   CSS, and JS in one file, opened and edited directly. The owner has little coding experience
   and edits it on github.com. Anything requiring npm, a bundler, or a toolchain is wrong here.
2. **No network at runtime.** A strict offline path matters at 3 a.m. in a nursery with bad
   signal. No CDNs, no fonts, no remote anything.
3. **Her data is hers.** It stays in `localStorage`. Never add telemetry, sync, or upload.
4. **Nothing destructive by accident.** Reading a record must not be able to change it, and
   deleting takes an explicit path plus a way back. Prefer undo over a confirm: a confirm at
   3 a.m. gets tapped through on reflex, and undo actually recovers the record.
5. **Touch targets stay big and few.** Prefer one obvious tap over a tidy dense layout.

## Data model

Three independent lists plus a live-timer slot, all in `localStorage`:

```
nursinglog.entries.v1   feedings
nursinglog.diapers.v1   diapers
nursinglog.meds.v1      medicine doses
nursinglog.active.v1    the feeding currently being timed, or absent
nursinglog.filter.v1    "all" | "feeds" | "diapers" | "meds" — the timeline view
nursinglog.backup.v1    epoch ms of the last backup, for the nudge
nursinglog.haptics.v1   "off" turns the buzz off; anything else (or absent) is on
nursinglog.rescue.*     text a list could not be read from, set aside verbatim
```

```js
feeding = { id, start,       // epoch ms, full precision
            end,             // epoch ms — when it finished, 1.12 and later
            leftSec, rightSec,   // seconds banked on each breast
            endSide,             // "L" | "R" | null — which side it finished on
            notes }

diaper  = { id, time,        // epoch ms
            pee, poop,       // booleans; at least one is true
            size,            // "S" | "M" | "L" | null — describes the poop only
            notes }

med     = { id, time,        // epoch ms
            name,            // trimmed, required — "Ibuprofen"
            dose,            // may be "" — "400 mg"
            notes }

active  = { start, side,     // "L" | "R"
            leftSec, rightSec,   // finished stretches only
            segStart,            // when the current side began
            paused }             // true while the clock is stopped
```

Rules the code depends on:

- **Side is derived, never stored.** `feedSide()` returns `B` when both sides have time, else
  whichever one does.
- **`end` is read through `feedEnd()`, never directly.** A record from before 1.12 has none, and
  the honest fallback is `start + leftSec + rightSec` — which is also the *earliest* an end can
  be, since a feeding cannot finish before the time on the breast has passed. `feedEnd()` treats
  a stored end below that as impossible and recomputes, which is what lets the editor carry the
  old end across an edit (`editingFeedEnd`): change only the notes and the true end survives,
  shorten the minutes and it is derived afresh. A paused feeding is the reason the two differ.
- **A pause banks time rather than remembering the break.** `segSeconds()` returns 0 while
  `paused`, and pausing folds the running stretch into `leftSec`/`rightSec` first, so a break of
  any length — including one that outlives a phone restart — is simply never on the clock.
  Nothing records how long a break lasted; only `end` shows it, as the gap between the minutes
  and the wall clock.
- **Totals are the sum of the displayed parts.** `feedMinutes()` adds the per-side rounded
  minutes when both sides have time, so a row never shows `14 + 7 = 20`.
- **`endSide` only ever names a side with time on it.** Stopping a second after switching must
  not leave it pointing at an empty side. `normalizeFeed()` enforces this.
- **`size` only survives with `poop: true`.** `normalizeDiaper()` strips it otherwise.
- **A dose with no medicine named is not a record.** Nothing else identifies it, so
  `normalizeMed()` returns null and the editor refuses to save. The amount is optional: plenty
  of things are taken without one being written down.
- **The medicine and its amount are still plain strings**, even though the editor picks them
  from `MED_NAMES` and `MED_DOSES`. The lists are a way to type less, not a set of valid
  values: "Something else" stores whatever is typed, and a record already holding a name or
  amount that is not on the list gets it added as an option of its own
  (`fillMedChoices()`), so opening a record can never quietly rename it. Editing a list means
  editing that one array — nothing stored refers to it.
- **A list that can't be read is never written over.** `readList()` used to hand back `[]` for
  anything that wouldn't parse, which looked exactly like an empty log — and the next save wrote
  over the only copy of it. Now the text is copied to a `nursinglog.rescue.*` key, the copy is
  read back to prove it stuck, and only then is the original let go of. If the copy can't be
  made, the key goes in `blockedKeys` and nothing may write to it at all. Individual records that
  don't normalize go in `quarantine` and are concatenated back on every write, so a record this
  version can't read isn't deleted by the next save either.
- **`writeList()` returns whether it actually wrote, and every caller checks.** A save that was
  refused must never be reported as a save: the stop handler leaves the feed running rather than
  ending it into thin air, the editors keep their sheet open, and `mergeRecords()` counts only
  what landed. The save functions update the in-memory list *after* a successful write, so what
  is on screen keeps matching what is on the phone.
- **Everything is normalized on read.** `normalizeFeed` / `normalizeDiaper` / `normalizeMed`
  are the single migration point, and also run on save and on import, so one function defines a valid record.
  Older feedings stored `{ minutes, side }`; those migrate on read, with `B` split evenly.

Bump the storage keys only with a migration in place — real data lives behind them.

## How the screen is put together

Top to bottom: feeding card (idle: two lines — when the last feed *started* and when it
*finished*, since feeds are counted start to start but time off the breast is the other half of
the question — plus Left/Right start buttons; running: total elapsed, a live per-side tile each,
Pause, Stop & Save), diaper card (time since last + Pee / Poop / Both), medicine card (time
since last dose + up to two recent medicines as one-tap buttons, plus a way to log something
else), today's stats, `All / Feeds / Diapers / Meds` filter, then the timeline grouped by day
with per-day totals.

The idle card points at the side the last feed ended on — that is where the next one picks up —
by giving that button the `sel` accent and the words *pick up here*. `pickUpSide()` decides it
and returns null for a hand-typed Both with no ending side, which is the only case with no
answer. It is recall, not instruction: the app is saying what happened last, not what to do.

The header carries two buttons: **?** opens the newborn basics, **⚙** opens the menu.

A red **alert card** above the feeding card is the only alarming thing on the main screen, and
the only thing that isn't dismissible: it appears when `renderRescue()` finds set-aside text,
a blocked key, or quarantined records. It earns the exception because it is the one problem she
has no other way of noticing. Everything else — the backup nudge included — stays a dot.

The timeline builds `HISTORY_DAYS` (14) days at a time, with a **Show older** button under it
that adds another fortnight. The window isn't stored: a fresh open starts at the recent days,
which is what is wanted at 3 a.m., and reaching further back is a deliberate thing to do. The
CSV, the PDF and the backup are unaffected — they always cover everything.

Eight bottom sheets: the **feeding editor**, the **diaper editor**, the **medicine editor**, the
**menu** (PDF summary, CSV export, JSON backup, restore, send an update, paste an update, what's
new, about, vibration), the **version log**, the **newborn basics**, **paste an update**, and
**unreadable data**.

**Every sheet has to be listed in `SHEETS`**, and every one that holds fields in `EDITORS`.
`SHEETS` drives three things at once: `sheetOpen()` (or the dim veil drops over a sheet mid-feed
and eats the next tap), the back gesture, and the backdrop tap. **Open and close them through
`showSheet()` / `hideSheet()`**, never by setting `.hidden` directly, or the sheet will not be
part of the history handling and back will close the app instead of it.

The basics sheet is a folded list of `<details>` built from `GUIDE`, a plain array of
`{ t, notes, days?, cls? }` near the top of the script. `days` renders the wet/dirty table.
Everything about it is deliberate and worth keeping: it reads nothing from the log and computes
nothing from it, it opens folded and scrolled to the top every time so its nine headings fit
one screen and any answer is one tap in, and the two `cls: "urgent"` sections are the only red
thing in the app. It carries **no medicine doses** — see *Deliberately not done*; the suite
asserts no `NNN mg` appears anywhere in it. Content is edited by editing the strings, which is
the point: the owner can do it on github.com without touching code.

Reading and editing a record are the *same sheet*. A row tap opens its editor with the
`locked` class on `.sheet`: every input `disabled`, chips inert via `pointer-events: none` with
unselected ones dimmed, the field borders dropped so the values read as text, and Close/Edit in
place of Cancel/Save/Delete. **Edit** unlocks it where it stands. Optional rows that are empty
(notes, poop size, dose) are hidden while locked, so reading never shows a blank box. `setLocked()`
drives all of it and all three editors go through it — a new editor should too, and any new field
must be inside the sheet so it gets disabled with the rest (it disables `input, select, textarea`).

The medicine editor's two fields are `<select>`s: the medicine and the amount, opening on
**Ibuprofen** and **400 mg** so the usual dose is one tap on Save. Amounts run 200–1000 mg in
200 mg steps plus *Not recorded*. Both lists end in *Something else*, which reveals the text box
underneath (`#mNameOtherWrap` / `#mDoseOtherWrap`); `syncMedOther()` shows and hides them, and
they stay hidden while reading, since the list itself carries the value then.

While a feed is running the app holds a **screen wake lock** and, after `DIM_AFTER` of no
touch, covers itself with `#dimVeil` — a black screen showing just the clock and the side, at
about 35% grey. The screen stays on so she can glance at it, without lighting a dark nursery.
A tap anywhere lifts the veil rather than reaching the controls beneath. The lock is dropped
when the feed ends and whenever the page is hidden (the browser revokes it anyway), and
re-taken on return. `wakeScreen()` is the single entry point: call it after anything that
starts or stops the timer.

Interaction rules worth preserving:

- A row tap opens a locked card. Editing is a second, deliberate tap. Delete lives inside the
  editors only, so it takes an intentional path to change or remove anything. This exists
  because tapping a row used to drop straight into a live form, where a stray touch on a
  highlighted chip silently rewrote the record you opened to check.
- The diaper and medicine quick buttons open the editor pre-filled — they do not write a
  record. Nothing is saved until Save, so a mis-tap costs a Cancel.
- The medicine buttons are the two most recent name+dose pairs, newest first, so the common
  case (the same tablet again) is one tap. They are derived from the log, never stored.
- The running timer survives app close, phone restart, and reload, because `segStart` and the
  banked seconds are persisted on every switch.
- Deleting is undoable, not confirmed. The removed record is held in the toast's closure and
  put back on Undo.
- **Stop & Save is undoable too**, by the same mechanism: its toast offers *Resume* rather than
  Undo (`toast()` takes the label as a third argument), and restoring drops the saved record and
  puts the banked seconds back on the clock. Stop sits under a thumb for the whole feed, so it
  gets mis-tapped; the closure refuses if a new feed has been started in the meantime rather
  than overwriting it. Like every undo here it lives in memory only, so a reload ends the offer.
- **A buzz confirms a tap without looking** (`buzz()`), on the actions that start, switch, pause,
  resume or stop the timer — the ones used in the dark. Nowhere else: a phone that buzzes at
  everything gets its vibration turned off, and the menu's Vibration line is how she does that.

## Conventions

- Plain ES5-style JS in one IIFE: `var`, `function`, no modules, no arrow functions, no
  optional chaining. It is consistent throughout — match it.
- Build DOM with `createElement` and `textContent`. Never interpolate user notes into
  `innerHTML`.
- Colors come from CSS custom properties defined once on `:root` and redefined under
  `@media (prefers-color-scheme: dark)`. Don't hardcode a color in a rule.
- Comments explain *why* something is the way it is, not what the line does. Keep them scarce.

## Gotchas found the hard way

- **Back is a reflex, and the app used to answer it by quitting.** With no history entry of its
  own, Android reads back in a standalone PWA as "leave the app" — so opening a record to check
  it and swiping back closed Nursing Log mid-feed. One entry now stands for *a sheet is open*,
  whichever one it is, and `popstate` spends it on closing the card. Two things make this work:
  the entry is settled in a microtask rather than on the spot, because the menu closes itself
  before opening what it was asked for and settling twice in one go would spend an entry and
  immediately push another (a microtask rather than a timer so it has always landed before the
  next tap — with `setTimeout(0)` a back press could beat the push and leave the app); and
  `pendingBack` counts the `history.back()` calls the app makes
  itself, so unwinding a sheet closed by button isn't mistaken for the user pressing back. Get
  that wrong and every sheet opened and closed leaves a dead entry, until back does nothing at all.
- **The backdrop may not discard an edit.** It is a wide invisible target beside a one-handed
  thumb, so `beingEdited()` makes a tap outside inert while an editor is unlocked; Cancel and
  Save stay the way out. Reading a card still closes on a tap outside, and back still behaves
  like Cancel — back and Cancel are deliberate, the backdrop is what gets hit by accident.
- **Network-first has to have a deadline.** `fetch()` rejects when there is no signal, which the
  `.catch()` always handled — but it *hangs* on a weak one, which is the nursery case, and the
  app sat on a blank screen for as long as the radio kept trying. `sw.js` now races the network
  against `NET_TIMEOUT` (1.5s) and serves the cache if it wins, while `event.waitUntil` keeps the
  request alive so a slow reply still refreshes the cache. A cache *miss* deliberately resolves
  nothing and leaves the network to answer: an empty response is worse than a slow one.
- **The timeline is capped, and its day totals are one pass.** `renderHistory()` used to walk
  every item again for each day heading — O(days × records), with a `new Date()` per step, on
  every save and every return to the app. Totals are now accumulated into a map in one pass, and
  only `historyDays` days are built. Both matter: a few months of records is thousands of rows.
- **`[hidden]` loses to any `display` rule.** `.row-2 { display: grid }` beat the browser's
  `[hidden]` and left panels on screen. There is a global `[hidden] { display: none !important }`
  guarding this — keep it.
- **`<input type="date|time">` only carries minutes.** Saving used to truncate seconds, so a
  diaper logged at 1:50:45 sorted *below* a feeding started at 1:50:30, and editing an entry's
  notes shifted its time backward by up to 59s. Both editors remember the exact instant they
  opened with (`feedBaseMs` / `diaperBaseMs`) and reuse it when the fields are untouched. Any
  new editor needs the same treatment.
- **The PDF is written by hand, not by a library.** `assemblePdf()` emits objects, a byte-exact
  `xref` table and a trailer; `put`/`box`/`rule` are the only drawing primitives. Two rules keep
  it valid: the file must stay single-byte (text is stripped to ASCII, so an offset equals a
  character count), and every `/Length` must match its stream exactly. Helvetica is referenced,
  never embedded, so `W_REG` / `W_BOLD` carry its advance widths for centring and right-aligning.
  `padLeft()` is deliberately not the app's `pad()` — an earlier version shadowed it and quietly
  broke every date field in the app.
- **Backups go through the share sheet.** `deliver()` hands the file to `navigator.share` when
  files can be shared, so it lands in Drive or email rather than Downloads, and falls back to a
  download otherwise. An `AbortError` means she dismissed the sheet — nothing was saved, so it
  must not fall back *or* record a backup. Only the JSON backup marks
  `nursinglog.backup.v1`; the CSV is a report, not a backup.
- **A browser can have `share()` without `canShare()`.** Refusing to share unless `canShare`
  exists means never opening the sheet on those browsers; `shareCandidate()` offers the file
  and lets the share reject instead. `fileShareLikely()` runs the same probe, so the menu
  wording and the About text can't promise a share sheet the browser won't give.
- **Chrome's share sheet refuses a `.json` file.** It allows a short list of extensions — text,
  CSV, PDF, images, media — so `canShare({files})` said no and the backup silently went to
  Downloads with no way to reach Drive. `shareBlob()` therefore retries textual files under a
  `.txt` name (`…-backup-20260815.json.txt`); the download fallback keeps the plain `.json`.
  Restore parses the contents, not the extension, and `#fileInput` accepts `.txt` for this
  reason. Don't test the share path with a stub that approves everything — the suite models
  the allowlist.
- **Import only ever adds, and matches on content rather than id.** `mergeRecords()` keys a
  feeding by `start|leftSec|rightSec`, a nappy by `time|pee|poop`, a dose by `time|name|dose`,
  and skips anything it already has — so a record she wrote can never be replaced by another
  phone's version of it, and re-sending the same days is free. Ids play no part, which is what
  lets two phones mint their own without coordinating. Both the file restore and the pasted
  update go through it, so there is one definition of what importing means.
- **`UPDATE_DAYS` has to outlast the gap between sends.** Overlapping sends are what makes a
  missed message free, but that only holds while the window is wider than the silence. At the
  three days this started with, a busy few days pushed the oldest records off the end with
  nothing to say so. It is a week now; beyond that the backup file is the answer.
- **Anything worded "how long ago" has to be on the tick.** The one-second interval refreshes the
  feed, diaper and medicine lines when idle — the medicine one was missed at first and sat frozen
  while the other two counted up. It refreshes the *line* (`renderMedSince()`), not the card:
  rebuilding `renderMedCard()` every second swaps the quick buttons out from under a thumb that
  is already on its way down. The same tick compares `shownDay` and redraws the totals and day
  headings when the date changes, since midnight lands mid-feed often enough to matter.
- **`visibilitychange` rereads every list.** It reloads feeds, diapers, meds and the active timer.
  Meds were missed at first — add new lists here.
- **A sent update is a backup file with fewer records and its defaults stripped.** `compactFeed`
  / `compactDiaper` / `compactMed` drop ids, empty notes and a derivable `end` — every one of
  them something `normalize*` puts back — so it stays the same format rather than becoming a
  second one, and stays small enough to text. Anything added to a record needs a decision here:
  carry it, or prove normalize can rebuild it.
- **A pasted update arrives wrapped in whatever the messaging app added.** `readPayload()` takes
  the outermost braces and ignores the rest, so pasting the whole message works — which is what
  she will actually do.
- **`VERSIONS` is the changelog and the version number both.** Newest first; `VERSIONS[0]` is
  what's running and what the menu line shows. Add an entry at the top in the same commit as
  the change, written for her rather than for a reviewer, and bump `CACHE` in `sw.js` alongside
  it. The version on screen is how she can tell whether the phone has picked up an update.
- **File names carry date *and* time** (`…-20260815-1127.json`). A second backup on the same
  day would otherwise land on the first, and Chrome asks "download again?" for a repeat name.
- **The backup toast says which way the file went** — "Backed up" only after the share sheet
  took it, "Saved to Downloads" otherwise. Don't collapse those: Downloads is the outcome this
  app is trying to avoid, and the wording is the only sign of which path ran.
- **The nudge counts from the oldest record when there is no backup yet**, so a log started
  today isn't nagged. Overdue is 10 days; it shows as a dot on the menu button and a highlighted
  line inside the menu, and nowhere else — this app does not get banners.
- **Storage is asked to persist.** `navigator.storage.persist()` runs at startup so the browser
  is less likely to evict the log under storage pressure. It is not a backup: clearing site data
  still wipes everything, which is why the JSON backup exists.
- **Bump `CACHE` in `sw.js`** when app files change, so phones drop the stale cache promptly.
  Fetch is network-first, so a stale cache is a slow update rather than a broken one.
- **Google's domains are blocked from this sandbox** (`dl.google.com` and Maven return 403 via
  the proxy), so Android tooling cannot be installed or built here. `sporadic92.github.io` is
  blocked too — you cannot fetch the live site to verify a deploy. Check the
  `pages build and deployment` workflow run instead.

## Testing

```
PLAYWRIGHT=/opt/node22/lib/node_modules/playwright/index.mjs node tests/app.test.mjs
```

Drop the `PLAYWRIGHT=` prefix if Playwright resolves from the project. The suite starts its own
static server on a random port, drives a phone-sized Chromium through the real UI, and prints
`PASSED n` plus a temp directory of screenshots. It fails the process on any failed check.

It covers per-side accrual and freezing on switch, timer persistence across reload, locked
cards staying inert under a force-tap, unlocking via Edit, editor round trips, diaper logging
and validation, filters, day grouping and totals, CSV and JSON round trips, de-duplicated
restore, migration of the older format, medicine logging and its editor, wake lock and dimming,
pausing (including that the clock stays frozen across a reload, and that the break never reaches
the total), taking a Stop & Save back, the suggested pick-up side, the buzz and its off switch,
the two-phone update — a second browser context logs records, shares a message, and the first
pastes it in, then checks that a second paste adds nothing and that a record of hers is left
untouched when his version of it arrives,
unreadable data in four shapes (text that won't parse, JSON that isn't a list, one bad record
among good ones, and a copy that can't be made because storage refuses the write), each in its
own context, asserting in every case that the original bytes are still there after a save and a
reload — that last one is the regression test for the bug this all exists for,
the backup nudge and share path,
the newborn basics sheet (folded on open, the diaper table, no doses, and that reading it
leaves the log untouched),
service worker registration, and loading with the network cut,
the back gesture (each sheet closing rather than the app, the menu-then-another-sheet handover
costing one entry, and — the one that catches a broken unwind — that after three sheets opened
and closed by button, one back still leaves the app),
the backdrop refusing to discard an edit while closing a card being read,
the "how long ago" lines all counting up, including that the medicine quick buttons are *not*
rebuilt while they do,
the midnight rollover, the timeline's fortnight cap and Show older, and a weak signal not holding
the app up. The PDF is parsed back: every xref offset must land on its object and every stream
length must match, since a wrong byte offset produces a file that opens in one reader and is
blank in another.

Harness notes. `navigator.wakeLock`, `navigator.share` and `navigator.canShare` are
read-only accessors in Chromium, so stubs go in via `Object.defineProperty`, not assignment.
Dimming is set to ten minutes everywhere except its own context — a veil appearing mid-test
silently swallows clicks. And a context's init script re-runs on every reload, so a stub that
must survive a reload belongs in `addInitScript`, not in a page `evaluate`.

Three more the newer sections needed. The test server serves a `/__sentinel` page, navigated to
before the app, so *left the app* is something the suite can see rather than infer from a sheet
still being open. It also has a `stall` flag that accepts requests and never answers them —
a weak signal, as opposed to `setOffline`, which models no signal at all; held responses are
destroyed at teardown or the server won't close. And two contexts move the clock rather than
wait for it: the "ago" lines are seeded a second short of the next minute, and the midnight
context overrides `Date.now` with a settable offset (`window.__clock`) starting four seconds
before local midnight. `new Date()` with no arguments is left alone, so don't lean on it there.

**Extend it with any behavior change** — it has caught several real bugs before they reached her
phone, including both gotchas above. Two habits that paid off: assert on what the user would
see (visible text, which sheet opened) rather than internals, and re-run the suite a few times
when timing is involved, since the timestamp bug first showed up only as flakiness.

Look at the screenshots too. Layout problems pass assertions and still look wrong.

## Deliberately not done

Not oversights — raise them before building:

- No pumping, weight, sleep, or bottle tracking. Scope is what she asked for. (Medicines were
  added in 1.9 because she asked for them — ibuprofen after the hospital. That is the bar.)
- No dosing advice, maximums, or "next dose due" arithmetic. The app shows what was taken and
  how long ago; deciding what is safe is not its job. The newborn basics sheet (1.11) holds to
  the same line: general guidance she could read anywhere, no numbers to take a medicine by,
  and nothing derived from her own log — a "you are behind on feeds today" would be this app
  diagnosing a baby, which it must not do.
- No reminders or notifications, medicine included. Nobody asked, and they need permissions
  plus a live worker.
- No multi-baby support, and no real multi-user support either. Two phones exchange records by
  message (1.13) because the owner asked for it the day it shipped; that is a one-way merge into
  her log, not shared state. Anything that makes the two logs equal partners — syncing, conflict
